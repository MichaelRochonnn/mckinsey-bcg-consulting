# 麦肯锡议题树结构规范

## 适用场景
- 构建麦肯锡风格的问题清单或议题树（Issue Tree）
- 准备大型战略汇报的演示结构
- 需要处理无法归入主要类别的闪光思想/异常见解
- 已完成MECE逻辑验证但需要最终结构化输出

## 执行步骤

### 1. 设定一级标题数量
严格控制一级标题（First-Level Headings）数量：
- **下限**：不少于2个（确保有足够维度展开分析）
- **上限**：不多于5个（避免结构过于复杂）
- **最佳实践**：设置为3个（对应麦肯锡文化中的"这个问题我们有三点看法"）

### 2. 识别并处理闪光思想
当团队提出有价值但难以归入主要类别的见解时：
- **禁止忽略**：不能因不符合主要分类而舍弃这些观点（无益于客户）
- **禁止强行单列**：不能随意将其列为独立的一级标题（会破坏2-5规则）
- **收容策略**：设立"其他问题"（Other Issues）作为收容类别

### 3. 放置"其他问题"类别
遵循位置规则确保专业性和得体性：
- **绝对禁止**：将"其他问题"放在清单头条（不得体且突兀）
- **推荐位置**：置于诸多子问题之中，保持低调不突兀
- **演示禁忌**：避免让"其他问题"出现在大型汇报的第一张幻灯片上
- **优先尝试**：尽量使闪光思想与现有的一级标题相符合，只有在确实无法归纳进已有标题时才使用"其他问题"类别

### 4. 数量控制与MECE验证
- 当异常见解数量为2-3个时，适合放入"其他问题"
- 若异常见解数量过多，需重新审视主要分类是否足够全面，而非简单堆砌到"其他问题"中
- 确保最终结构符合MECE原则（相互独立，完全穷尽）

## 关键约束
- 遵循麦肯锡内部汇报标准
- 适用于大型汇报场景
- 前置条件：已完成MECE逻辑验证的问题清单

## 文化提示
麦肯锡文化中常以"这个问题我们有三点看法"自嘲，体现了对"3个一级标题"这一黄金标准的偏好。保持这一结构有助于符合咨询行业的沟通惯例。
