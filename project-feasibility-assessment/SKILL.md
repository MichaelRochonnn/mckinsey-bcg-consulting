# 项目可行性评估与问题分解

## 适用场景
- 收到客户问题陈述
- 初步了解问题领域
- 可获得的时间预算信息
- 上级（老板）的支持渠道

**不适用**：已经启动的紧急救火项目

## 执行步骤

### 1. 建立问题边界感知
在"紧锣密鼓地开始寻找解决方案之前"，首先要对问题的边界有一个"整体的感觉"（overall sense of boundaries），避免盲目切入。

### 2. 执行可行性评估
判断"你和你的团队能在规定时间解决这个问题吗？"

**评估维度**：
- 时间充足性
- 团队能力匹配度
- 问题复杂度

**决策分支**：如果不能在规定时间内解决，有两个并行选项：
- a) 去争取更多的时间（negotiate for more time）
- b) 坐下来和老板商量，将大问题分解成容易解决的小问题（decompose into manageable pieces）

### 3. 明确子问题成果物
搞清楚每个小问题的最终成果是什么，具体可能包括：
- 一条建议（a recommendation）
- 一套新的实施计划（a new implementation plan）
- 一种新的产品设计（a new product design）
- 其他具体可交付成果

### 4. 资源计算与承诺获取

**计算步骤**：算出完成任务需要多少资源（人力、时间、资金、数据访问权限等）

**承诺步骤**：从老板那里获得拥有这些资源的正式承诺（secure commitment），确保资源可用性

### 5. 前置价值实现
提前完成上述步骤"可以省去几个月的麻烦"，避免项目中途发现不可行或资源不足导致的危机。

## 关键变量
- **问题边界**：问题的整体范围和界限
- **规定时间**：客户或组织要求的项目完成期限
- **子问题成果物**：建议、实施计划、产品设计等具体交付物类型
- **资源需求**：完成任务所需的人力、时间、资金等资源量化指标

## 决策门
- 边界感知检查点
- 可行性判断点
- 资源承诺确认点
