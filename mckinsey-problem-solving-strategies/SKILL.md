# 应对棘手问题的策略选择

## 何时使用

项目出现以下情况时启动策略选择：
- 项目碰壁且继续下去无好处
- 原有方案无法推进
- 面临政治阻力或资源限制
- 需要基于商业理性判断调整方向

**不适用**：技术性错误导致的失败

## 决策树

```
项目受阻且继续无益
├── 价值判断偏差 → 策略一：重新定义问题
├── 资源限制阻碍 → 策略二：调整实施方案
└── 利益冲突阻碍 → 策略三：攻克政治难关
```

## 策略一：重新定义问题

### 操作
告诉客户他们的问题不是X，而是Y。

### 适用条件
- 解决Y问题会为客户带来很多附加价值
- 纠缠于X问题只会得不偿失

### 风险控制
| 时机 | 结果 |
|------|------|
| 尽早确立转变 | 表现出强大的商业判断力 |
| 几周后才转变 | 很可能面临被指责逃避问题的风险 |

## 策略二：调整实施方案

### 核心认知
设计理想化方案很容易，但通常需考虑客户现有的人力资源限制。

### 操作策略
- 如果需要人事变动，做长期规划
- 别为不能马上实施解决方案而担心
- 随着相关人员离开客户公司，逐步"调整"实施方式
- 最终达到最好结果

## 策略三：攻克政治难关

### 核心认知
- 商业领域的大多数人是理性的（至少在经营生意时）
- 激励总能起到作用
- 所谓政治就是人在为自己的利益而行动
- 反对势力通常意味着解决方案对某个人具有负面意义

### 执行步骤

1. **分析影响**
   - 分析解决方案如何影响公司里的各个利益方

2. **形成共识**
   - 让各方对公司的变化形成共识
   - 考虑他们的动机
   - 考虑推进政治的组织因素

3. **调整方案**
   - 必要时改变解决方案，使其变得可以接受

> **理念**：政治是可能性的艺术。

## 策略选择检查清单

- [ ] 阻碍性质是否已明确区分（价值偏差/资源限制/利益冲突）？
- [ ] 重新定义问题的时机是否足够早？
- [ ] 实施方案调整是否考虑了长期人事变动？
- [ ] 政治分析是否识别了各方的真实动机？
- [ ] 是否准备了方案调整空间以换取政治接受？
